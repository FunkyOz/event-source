# Design: funkyoz/event-source 2.0

Status: **implemented**. The decisions are in section 12, and the differences from this design in section 13.

## 1. Goals

Version 2.0 is a new API under a new name (`funkyoz/event-source`, namespace `FunkyOz\EventSource\`).

1. **Framework-agnostic core**: no dependencies besides PHP. It works in plain PHP out of the box.
2. **Native responses for frameworks**: Symfony and Laravel users get a response object their framework sends,
   so middleware, listeners and profilers keep working.
3. **The whole lifecycle handled for you**: setup and cleanup, polling, heartbeats, maximum duration,
   disconnects, errors and resuming with `Last-Event-ID`.
4. **Easy to test**: testing helpers ship with the library.
5. **Correct and safe output**: follows the specification and rejects input that would corrupt the stream.

### Non-goals

- **Async runtimes** (ReactPHP, Swoole, RoadRunner, Octane workers): the loop blocks while it sleeps, which would
  freeze an event loop. They need a different runner, which is out of scope for 2.0.
- **Fan-out to many clients / pub-sub**: that's what [Mercure](https://mercure.rocks) is for.
- **A JavaScript client**: the browser's `EventSource` is enough.
- **PSR-7**: possible later as another bridge (see section 9).

## 2. Positioning

Both big frameworks now ship basic SSE support. This library has to offer more than that.

| | Symfony `EventStreamResponse` (7.3+) | Laravel `response()->eventStream()` (11+) | **funkyoz/event-source 2.0** |
|---|---|---|---|
| Plain PHP, no framework | ❌ | ❌ | ✅ |
| Same API in every framework | ❌ | ❌ | ✅ |
| Event ids and `retry` | ✅ | ❌ | ✅ |
| `Last-Event-ID` for resuming | do it yourself | do it yourself | ✅ built in |
| Polling loop with a fixed interval | do it yourself | do it yourself | ✅ |
| Setup and cleanup hooks, also after a disconnect | ❌ | ❌ | ✅ |
| Heartbeats against proxy timeouts | do it yourself | ❌ | ✅ |
| Maximum duration | ❌ | ❌ | ✅ |
| Error handling that keeps the stream valid | ❌ | partial | ✅ |
| Testing helpers | ❌ | ❌ | ✅ |
| Symfony 6.4 | ❌ | — | ✅ |

## 3. Architecture

```
┌────────────────────────────────────────────────────────────────┐
│ Event: immutable value object, formatted by EventFormatter     │  pure, no I/O
├────────────────────────────────────────────────────────────────┤
│ EventStream: definition (listeners, timing, headers)           │
│ StreamRunner: runs a definition against an Output and a Clock  │  no dependencies
│ Stream: what listeners receive (send, stop, lastEventId, …)    │
├────────────────────────────────────────────────────────────────┤
│ Output, Clock: interfaces                                      │
│   PhpOutput, StreamOutput, SystemClock: implementations        │
│   Testing\MemoryOutput, Testing\FakeClock: for tests           │
├────────────────────────────────────────────────────────────────┤
│ Native:   EventStream::send()                       built in   │
│ Bridge\Symfony\StreamedResponseFactory     symfony 6.4 – 8.x   │
│ Bridge\Laravel\EventSourceServiceProvider  laravel 11 – 13     │
└────────────────────────────────────────────────────────────────┘
```

Key decisions:

- **The definition is separate from a run.** An `EventStream` holds no runtime state, so it can be defined once
  (in a service, for example) and sent to many clients. Each run gets its own `Stream`.
- **Users only learn three types**: `Event`, `EventStream` and `Stream`. `Output` and `Clock` matter only to
  adapter authors and to tests.
- **All durations are in seconds, as `float`**: `every()`, `heartbeat()`, `maxDuration()`, `retry`. The library
  converts `retry` to milliseconds on output. In 1.x, `retry` was in seconds but `setSleep()` took an `int`.

## 4. Usage

### Defining a stream

The definition is the same in every environment:

```php
use FunkyOz\EventSource\Event;
use FunkyOz\EventSource\EventStream;
use FunkyOz\EventSource\Stream;

$stream = EventStream::create()
    ->every(1.0)
    ->heartbeat(15)
    ->maxDuration(300)
    ->onStart(function (Stream $stream) use ($user) {
        $stream->send(Event::json('hello', ['user' => $user->id]));
    })
    ->onTick(function (Stream $stream) {
        // lastEventId(): from the Last-Event-ID header at first, then the last id sent
        foreach (Notification::newerThan($stream->lastEventId()) as $notification) {
            $stream->send(Event::json('notification', $notification, id: (string) $notification->id));
        }
    })
    ->onStop(fn (Stream $stream) => $logger->info('Stream closed', ['reason' => $stream->stopReason()->name]))
    ->onError(fn (\Throwable $e, Stream $stream) => $stream->send(new Event('error', 'Temporary problem')));
```

### Plain PHP

```php
$stream->send(); // sends the headers, reads Last-Event-ID from $_SERVER, streams
```

### Symfony

```php
use FunkyOz\EventSource\Bridge\Symfony\StreamedResponseFactory;

#[Route('/events')]
public function events(Request $request): StreamedResponse
{
    return StreamedResponseFactory::create($this->notifications->stream(), $request);
}
```

### Laravel

The service provider is registered automatically (package auto-discovery) and adds a `sse` response macro:

```php
Route::get('/events', fn (Request $request) => response()->sse($stream));
```

The name `sse` avoids a clash with Laravel's own `eventStream`, and is unused elsewhere (see section 7). Laravel
accepts Symfony responses, so `StreamedResponseFactory::create($stream, $request)` also works there.

### Finite streams with a generator

```php
$stream = EventStream::fromGenerator(function (Stream $stream) use ($job) {
    foreach ($job->run() as $percent) {
        yield Event::json('progress', ['percent' => $percent]);
    }
    yield new Event('done');
});
```

### Ending for good

The browser reconnects whenever a stream ends. To tell it to stop, end with an event the page closes on, or answer
the next request with `204 No Content`:

```php
EventStream::sendNoContent();                    // plain PHP
return StreamedResponseFactory::noContent();     // Symfony
return response()->noContent();                  // Laravel already has it
```

### Testing

```php
use FunkyOz\EventSource\Testing\StreamTester;

$result = StreamTester::for($stream)
    ->withLastEventId('41')
    ->disconnectAfter(3)   // iterations
    ->run();

self::assertCount(2, $result->events('notification'));
self::assertSame('42', $result->events()[0]->id);
self::assertSame(StopReason::ClientDisconnected, $result->stopReason());
self::assertSame([1.0, 1.0], $result->sleeps());  // no real waiting
```

## 5. Public API

Everything is `final` unless noted. Signatures are indicative and may change during implementation.

### `Event`

An immutable value object.

```php
final class Event
{
    public function __construct(
        public readonly ?string $name = null,   // null = unnamed (the browser's "message" event)
        public readonly string $data = '',
        public readonly ?string $id = null,
        public readonly ?float $retry = null,   // seconds
    );

    public static function json(?string $name, mixed $data, ?string $id = null, ?float $retry = null): self;

    public function withName(?string $name): self;
    public function withData(string $data): self;
    public function withId(?string $id): self;
    public function withRetry(?float $retry): self;
}
```

- **The default name is `null`**, not `'message'`. The output is shorter, and the browser handles both the same way.
- **`name` comes first**, as in 1.x: `new Event('tick', 'data')`. Migrating code keeps the same argument order.
- **Validation**: `name` and `id` must not contain line breaks, and `id` must not contain `NUL`. Otherwise one
  value could inject extra fields into the stream. `retry` must not be negative. Invalid values throw
  `InvalidArgumentException`.
- **`json()`** encodes with `JSON_THROW_ON_ERROR`, so encoding errors surface instead of sending `false`.
- **Public readonly properties instead of getters**: less code, and `$event->id` reads naturally.

### `EventStream`

The definition of a stream. Fluent and mutable; each method returns `$this`.

```php
final class EventStream
{
    public static function create(): self;
    public static function fromGenerator(callable $generator): self;  // callable(Stream): iterable<Event>

    public function every(float $seconds): self;          // default 1.0, listener mode only
    public function heartbeat(?float $seconds): self;     // default null (off)
    public function maxDuration(?float $seconds): self;   // default null (no limit)
    public function retry(?float $seconds): self;         // sent once, at the start
    public function header(string $name, string $value): self;
    public function headers(array $headers): self;

    public function onStart(callable $listener): self;    // callable(Stream): void
    public function onTick(callable $listener): self;     // callable(Stream): void
    public function onStop(callable $listener): self;     // callable(Stream): void
    public function onError(callable $listener): self;    // callable(\Throwable, Stream): void

    /** @return array<string, string> headers to send, including the SSE defaults */
    public function getHeaders(): array;

    public function send(): void;                          // native: plain PHP
    public static function sendNoContent(): void;          // native: 204

    public function run(Output $output, ?string $lastEventId = null, ?Clock $clock = null): StopReason;
}
```

- **`run()` is the integration point for adapters.** It writes the body only; the adapter sends the headers.
- **The default headers** are `Content-Type: text/event-stream`, `Cache-Control: no-cache` and
  `X-Accel-Buffering: no`. `header()` adds or replaces them.
- **`onTick` replaces "write listener"**: the name says when it runs.
- **Calling `onTick()` on a generator stream throws `LogicException`**, so does `every()`. The two modes don't mix.

### `Stream`

Passed to every listener. One instance per run.

```php
final class Stream
{
    public function send(Event $event): void;     // writes and flushes immediately
    public function comment(string $text = ''): void;
    public function stop(): void;                 // ends after the current listener returns
    public function isStopped(): bool;
    public function lastEventId(): ?string;       // Last-Event-ID header, then the last id sent
    public function iteration(): int;             // 0 in onStart, then 1, 2, 3…
    public function elapsed(): float;             // seconds since the start
    public function stopReason(): ?StopReason;    // set in onStop
}

enum StopReason
{
    case Stopped;              // a listener called stop(), or the generator finished
    case ClientDisconnected;
    case MaxDurationReached;
    case Error;
}
```

- **`send()` flushes right away.** In 1.x output was flushed at the end of an iteration, which delayed events
  for no benefit. SSE events are small, and immediate delivery is what users expect.
- **`lastEventId()` follows what was sent**, so the common "send what's new since the last id" loop needs no
  external variable.

### Output and clock

For adapters and tests.

```php
interface Output
{
    public function open(): void;               // before the first write (e.g. output buffering)
    public function write(string $chunk): void;
    public function flush(): void;
    public function isConnectionAborted(): bool;
    public function close(): void;              // always called, also after an error
}

interface Clock
{
    public function now(): float;               // seconds, monotonic
    public function sleep(float $seconds): void;
}
```

| Implementation | Purpose |
|---|---|
| `PhpOutput` | `echo`, output buffering, `flush()`, `connection_aborted()`, `ignore_user_abort()` with restore |
| `StreamOutput` | Any PHP stream resource, e.g. a file or `php://stdout` |
| `SystemClock` | `hrtime()` and `usleep()` |
| `Testing\MemoryOutput` | Keeps the output and parses it back into events; can simulate a disconnect |
| `Testing\FakeClock` | Moves time forward on `sleep()` instead of waiting |
| `Testing\StreamTester` | Runs a stream with the two above and returns the result |

## 6. Runtime behavior

### Listener mode

```
output->open()
onStart listeners
loop:
    stop requested or max duration reached?  → end
    onTick listeners
    client disconnected?                     → end
    sleep until the next tick, sending heartbeats on time while waiting
onStop listeners (with stopReason set)
output->close()                              always, in finally
```

### Generator mode

```
output->open()
onStart listeners
for each yielded event:
    send it
    stop requested, client disconnected or max duration reached?  → end
onStop listeners
output->close()
```

Heartbeats can't be sent while the generator itself is blocked, for example inside `sleep()` in user code. This
will be documented.

### Details

- **Heartbeats**: sent as a comment line (`:` plus a newline) when nothing was written for `heartbeat` seconds.
  If `every()` is longer than `heartbeat()`, the runner sleeps in shorter steps so heartbeats stay on time. A
  heartbeat also detects disconnects sooner.
- **Disconnect detection**: checked after every flush. PHP only notices a closed connection when it writes.
- **Max duration**: checked before each tick. The stream ends normally, and the browser reconnects with
  `Last-Event-ID`.
- **Errors**: an exception in `onStart` or `onTick`, or from the generator:
  1. calls the `onError` listeners, which can still send an event;
  2. runs the `onStop` listeners with `StopReason::Error`;
  3. closes the output;
  4. rethrows the exception **only if there are no `onError` listeners**, so errors are never silent by default.

  An exception inside `onStop` or `onError` is not caught: it's a bug in the cleanup code.
- **Retry**: if set on the stream, sent once as the first line. An event's own `retry` overrides it.

## 7. Bridges

### Symfony (`Bridge\Symfony`)

```php
final class StreamedResponseFactory
{
    public static function create(EventStream $stream, ?Request $request = null): StreamedResponse;
    public static function noContent(): Response;
}
```

- Returns a plain `StreamedResponse` with the stream's headers. Its callback calls
  `$stream->run(new PhpOutput(), $request?->headers->get('Last-Event-ID'))`.
- Works with `symfony/http-foundation` 6.4 to 8.x. It doesn't use `EventStreamResponse`, which only exists from 7.3.

### Laravel (`Bridge\Laravel`)

```php
final class EventSourceServiceProvider extends ServiceProvider
{
    // Registers ResponseFactory::macro('sse', fn (EventStream $stream) => …)
    // using request() for Last-Event-ID
}
```

- Registered through `extra.laravel.providers` in `composer.json`; the extra entry is harmless for non-Laravel users.
- Supports Laravel 11 to 13. Laravel 11 is the first version that runs on PHP 8.2 and Symfony 7.
- **The name `sse` is free.** It was checked on 2026-10-23 against the whole source of Laravel 11.57, 12.70 and
  13.38, which only has `eventStream`, and against the 7 most-downloaded Laravel SSE packages on Packagist.
- **Guard against future conflicts.** In Laravel, a real method silently takes priority over a macro with the same
  name. If `ResponseFactory` already has an `sse` method or macro, the service provider throws a
  `LogicException` at boot, explaining that `StreamedResponseFactory` can be used instead. The weekly CI run
  installs the latest Laravel, so a conflict shows up there before it reaches users.

## 8. Package

```json
{
    "name": "funkyoz/event-source",
    "require": { "php": "^8.2" },
    "suggest": {
        "symfony/http-foundation": "To return Symfony responses (^6.4 || ^7.0 || ^8.0)",
        "laravel/framework": "To use the response()->sse() macro (^11.0 || ^12.0 || ^13.0)"
    },
    "autoload": { "psr-4": { "FunkyOz\\EventSource\\": "src/" } },
    "extra": { "laravel": { "providers": ["FunkyOz\\EventSource\\Bridge\\Laravel\\EventSourceServiceProvider"] } }
}
```

- **Development dependencies**: `symfony/http-foundation` and `orchestra/testbench` (to test the Laravel bridge
  in a real application) are added to `require-dev`.
- **CI**: the existing matrix (PHP 8.2–8.5, lowest and highest dependencies) also covers the bridges. Composer
  picks the Laravel and Symfony versions that fit each PHP version.
- **Bridge classes** are loaded only when used, so plain-PHP users need nothing extra.

## 9. Decided against, for now

| Option | Reason |
|---|---|
| PSR-7 as the core | PSR-7 bodies are pulled by an emitter and have no flushing; SSE is pushed. It would also force users to choose PSR-17 factories. |
| PSR-7 bridge in 2.0 | Disconnect detection depends on the server running it. To add when someone asks. |
| Building on Symfony's `EventStreamResponse` | Only exists from 7.3, and the core must not depend on Symfony. |
| PSR-20 `ClockInterface` | It has no `sleep()`, and it returns `DateTimeImmutable`, which is too coarse for heartbeats. |
| Closing the session automatically | It would surprise users who write to the session in a listener. Documented instead. |
| Split packages per bridge | Three times the release work for a small library. Possible later. |

## 10. Migration from 1.x

| 1.x (`dessimoney/event-source`) | 2.0 (`funkyoz/event-source`) |
|---|---|
| `composer require dessimoney/event-source` | `composer require funkyoz/event-source` |
| `EventSource\` namespace | `FunkyOz\EventSource\` |
| `new EventSender()` | `EventStream::create()` |
| `addStartListener(fn (EventBufferInterface $b) => …)` | `onStart(fn (Stream $s) => …)` |
| `addWriteListener(…)`, return `true` to stop | `onTick(…)`, call `$s->stop()` |
| `addStopListener(…)` | `onStop(…)`, with `$s->stopReason()` |
| `$buffer->write($event)` | `$stream->send($event)` |
| `new Event('name', 'data', 'id', 3)` | Same order: `new Event('name', 'data', 'id', 3)`. The default name is now `null` |
| `$event->getData()` / `setData()` | `$event->data` / `withData()` |
| `setSleep(1)` | `every(1.0)` |
| `addHeader()` / `addHeaders()` | `header()` / `headers()` |
| `$sender->send()` returning a sent `StreamedResponse` | Plain PHP: `$stream->send()`. Symfony: `StreamedResponseFactory::create()`. Laravel: `response()->sse()` |
| `setBuffer()`, `EventBufferInterface`, `EventBuffer` | Removed. Use `Output` (adapters) or `Testing\MemoryOutput` (tests) |
| `RuntimeInterface`, `PhpRuntime` | Replaced by `Output` and `Clock` |
| Requires `symfony/http-foundation` | No dependencies |

Both packages can be installed at the same time, because their namespaces differ. A project can migrate one
endpoint at a time.

## 12. Decisions

Answers to the review questions:

1. **`Event` argument order**: `name` stays first, as in 1.x.
2. **Laravel macro name**: `response()->sse($stream)`, after checking that no other code uses the name, with a
   guard against future conflicts (section 7).
3. **Flushing**: `Stream::send()` flushes every event immediately. There's no reason to batch.
4. **Errors without `onError`**: the exception is rethrown, after the stop listeners and cleanup have run.

## 13. Implementation notes

Where the implementation differs from, or adds to, the design above:

- **Namespaces**: `Output`, `Clock`, `PhpOutput`, `StreamOutput` and `SystemClock` are in the root namespace. The
  runner and its state are in `Internal\`, marked `@internal`.
- **No tick listeners**: a stream created with `create()` but without `onTick` listeners ends right after `onStart`,
  instead of idling until the client leaves.
- **`PhpOutput` doesn't open an output buffer.** It flushes the current one, if any, like Symfony's and Laravel's
  own streamed responses. There's nothing left to close afterwards.
- **Testing helpers**: besides `StreamTester`, `MemoryOutput` and `FakeClock`, there are `EventParser`,
  `ParsedStream` and `StreamResult`. `StreamTester` throws after 10,000 iterations, so a test can't hang, and the
  limit can be changed with `iterationLimit()`.
- **Laravel macro**: Laravel binds macros to the `ResponseFactory`, so the macro can't be a `static` closure, and
  the application is captured in a variable. Booting twice doesn't throw: the provider remembers it registered the
  macro.
- **Header validation**: header names and values are validated like event names and ids, against header injection.
- **No heartbeats in generator streams**: heartbeats are sent while waiting between ticks, and a generator stream
  never waits, so `heartbeat()` throws a `LogicException` there, like `every()` and `onTick()`.
- **Laravel 12 and 13 only**, instead of 11 to 13. Every Laravel 11 release is affected by security advisories
  published in 2026 and fixed only in Laravel 12.60+ and 13.x, as Laravel 11 is end-of-life. Composer refuses to
  install them by default, so Laravel 11 can't be tested, and shouldn't be recommended.
- **Tests**: the `core` suite includes end-to-end tests that send streams through PHP's built-in server over real
  HTTP connections, including a client disconnection. CI also runs the core with no framework installed, and the
  Symfony bridge with Symfony 6.4 alone, since Laravel requires Symfony 7 or newer.
